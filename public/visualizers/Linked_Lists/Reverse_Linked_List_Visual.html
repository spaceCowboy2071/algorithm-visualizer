Reverse Linked List

LeetCode #206 — Pointer Reversal Visual Walkthrough

Iterative Pointer Reversal Easy Linked Lists

1 — What's the problem?

Reverse a singly linked list. Each node only has .val and .next — no indices, no random access, no backward pointers.

Not like arrays: You can't index into a linked list. No list[3]. To reach a node, you walk there via .next pointers. You use while loops, not for loops.
Three pointers, four operations per step: prev (the reversed portion), curr (the node being processed), nxt (saved before we break the link). Each step: save → flip → advance prev → advance curr.

def reverseList(self, head): prev, curr = None, head # prev=None (new tail), curr=head while curr: # until curr walks off the end nxt = curr.next # SAVE next before we break link curr.next = prev # FLIP pointer backward prev = curr # ADVANCE prev forward curr = nxt # ADVANCE curr forward return prev # prev is new head (curr is None)

O(n) time, O(1) space. This is the go-to answer for interviews.

def reverseList(self, head): if not head or not head.next: # base: empty or single node return head new_head = self.reverseList(head.next) # recurse to end head.next.next = head # my next node points back at me head.next = None # break my forward pointer return new_head # pass new head all the way up

O(n) time, O(n) space (call stack). Know this for follow-up questions — Meta specifically asks for both.

Iterative: O(n) time, O(1) space

Visit each node once. Only three pointer variables.

Recursive: O(n) time, O(n) space

Same traversal, but call stack holds n frames.

Pattern connection: Pointer reversal is the building block for Reorder List (reverse second half then merge), Palindrome Linked List (reverse half and compare), and the reverse portion of Reverse Nodes in k-Group. The three-pointer walk also appears in Merge Two Sorted Lists.
