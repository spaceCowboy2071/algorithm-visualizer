Clone Graph

LeetCode #133 — Iterative DFS, Recursive DFS & BFS Visual Walkthrough

BFS/DFS + Hash Map Medium Graphs

1 — What's the Problem?

Given a reference to a node in a connected, undirected graph, return a deep copy (clone) of the entire graph. Every node in the clone must be a brand new object — zero shared references with the original.

Each node has a val (integer, unique) and a neighbors list (pointers to other nodes).

Key challenge: Nodes can form cycles. If node 1 points to node 2, and node 2 points back to node 1, a naive copy would loop forever. You need a way to say "I already cloned this node" and retrieve that clone instead of creating a duplicate.

The solution: Use a hash map (Python dict) that maps each original node to its clone. This serves double duty — it's your visited check AND your clone lookup table. Two birds, one dictionary.

o_to_n[original_node] = Node(original_node.val)   # key: original → value: clone

2 — DFS vs BFS: What's the Difference?

Both visit every reachable node exactly once. The difference is the order they visit them, which comes from one data structure swap.

FIFO

BFS — Breadth First Search

Uses a queue (first in, first out).

Explores level by level — all neighbors first, then their neighbors. Like ripples spreading from a stone dropped in water.

q = deque([start])
current = q.popleft()
q.append(neighbor)

Best for: Shortest path in unweighted graphs, level-order traversal.

LIFO

DFS — Depth First Search

Uses a stack (last in, first out).

Dives as deep as possible down one path before backtracking. Like walking a maze — go until you hit a dead end, then back up.

stk = [start]
current = stk.pop()
stk.append(neighbor)

Best for: Exhaustive path search, backtracking, tree problems, cycle detection.

The only code difference: deque + popleft() (BFS) vs list + pop() (DFS). Everything else — the visited check, the neighbor loop, the overall structure — is identical.

Recursive DFS — The Third Option

Instead of an explicit stack, you let the call stack do the work. Each recursive call pushes a frame; returning pops it. Usually produces the shortest, cleanest code. Same traversal order as iterative DFS.

Trade-off: Python has a default recursion limit of ~1000. For very deep graphs, iterative is safer.

3 — Algorithm Logic (All Three Approaches)

The core pattern is the same regardless of traversal method.

Guard clause: if not node → return None
▼
Seed: Create clone of start node, store in dict
▼
Traverse: Pop/recurse on each node
▼
For each neighbor: if not in dict → create clone, add to dict, push/enqueue/recurse
▼
Wire: Append clone of neighbor to clone of current node's neighbors list
▼
Return: o_to_n[start node] — the clone of the entry point
The dict does double duty: if nei not in o_to_n is your visited check. o_to_n[nei] retrieves the clone. No separate visited set needed.

Time: O(V + E)

Visit every vertex once (V), traverse every edge once from each side (E). Same for all three approaches.

Space: O(V)

The dict stores V clones. Stack/queue/call-stack holds at most V nodes. Total: O(V).
