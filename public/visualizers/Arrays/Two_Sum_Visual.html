1 — What's the Problem?

Given an array nums and a target, return the indices of two numbers that add up to the target. Each input has exactly one solution. You can't use the same element twice.

2 — The Key Insight: Check Before You Store

Brute force checks every pair — O(n²). The hash map approach is O(n): for each element, compute the complement (target - nums[i]) and check if it already exists in the map.

The pattern: As you scan left to right, the map accumulates every value you've seen and its index. At each new element, you ask: "Is my other half already in there?" If yes, you're done. If no, store yourself and move on.
For each nums[i]: compute diff = target - nums[i]
▼
Is diff in the hash map?
▼
YES
Return [map[diff], i]
NO
Store map[nums[i]] = i
Order matters: Check before storing. This prevents an element from matching with itself. For example, [3, 3] target 6 — if you stored first, index 0 would find itself.

4 — Complete Implementation

def twoSum(self, nums: List[int], target: int) -> List[int]: prevMap = {} # val → index for i, n in enumerate(nums): diff = target - n # what do I need? if diff in prevMap: # seen it already? return [prevMap[diff], i] # done! prevMap[n] = i # store for later

Time: O(n)

Single pass. Hash map lookup is O(1) average.

Space: O(n)

Map stores up to n entries in the worst case (complement found at the last element).

Pattern connection: The "check map for complement" pattern extends directly to 3Sum (fix one element, two-pointer for the rest) and 4Sum. The hash map lookup trick also appears in Group Anagrams (sorted key → list of anagrams) and Longest Consecutive Sequence (set membership check).
